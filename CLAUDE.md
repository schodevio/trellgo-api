# TrellGo API — Coding Instructions

## Project Overview

REST API for a Trello-like app. Built with Go, Fiber v3, PostgreSQL, sqlc, and Goose.

**Module:** `github.com/schodevio/trellgo`

---

## Architecture

```
cmd/api/          → entrypoint (main.go)
internal/
  app/            → server bootstrap, DI container, router, middleware
  module/<name>/  → feature modules
  platform/       → shared infrastructure packages
db/
  migrations/     → Goose SQL migration files
  queries/        → sqlc SQL query files
  sqlc/           → generated Go code — NEVER edit manually
```

---

## Module Structure

Every feature lives in `internal/module/<name>/` and follows this layout:

| File | Purpose |
|---|---|
| `module.go` | Wires repo→service→handler, exposes `New()` and `RegisterRoutes()` |
| `handler.go` | HTTP layer — parses body, validates, calls service, returns JSON |
| `service.go` | Business logic — interface + struct, unexported constructor |
| `repository.go` | DB access via sqlc — interface + struct, unexported constructor |
| `dto.go` | Request/response structs with `json` and `validate` tags |
| `utils.go` | Module-private helpers (e.g. `hashPassword`) |

### Constructors

- `New(queries *sqlc.Queries) *Module` — public, used in `container.go`
- `newService`, `newRepository`, `newHandler` — unexported, only called from `module.go`

### Module wiring example

```go
func New(queries *sqlc.Queries) *Module {
    repo    := newRepository(queries)
    service := newService(repo)
    handler := newHandler(service)
    return &Module{Service: service, handler: handler}
}
```

### Route registration

Modules register their own routes via `RegisterRoutes(router fiber.Router)`.
All routes live under the `/api/v1` prefix — set globally in `router.go`.

```go
func (m *Module) RegisterRoutes(router fiber.Router) {
    g := router.Group("/<module-name>")
    g.Post("/action", m.handler.SomeHandler)
}
```

## Adding a New Module

1. Create `internal/module/<name>/` with `module.go`, `handler.go`, `service.go`, `repository.go`, `dto.go`
2. Add `*<name>.Module` field to `Container` in `internal/app/container.go`
3. Instantiate it in `NewContainer` with `<name>.New(queries)`
4. Call `cntr.<Name>.RegisterRoutes(api)` in `setupRoutes` in `internal/app/router.go`
5. Add SQL queries to `db/queries/<name>.sql` and run `make sqlc`

## Database

### Schema & Migrations

- Migration files: `db/migrations/<seq>_<description>.sql`
- Format: Goose `-- +goose Up` / `-- +goose Down`
- Sequence: zero-padded 5-digit prefix (e.g. `00002_`)
- IDs: `TEXT PRIMARY KEY DEFAULT gen_random_uuid()` — generated by PostgreSQL via the `pgcrypto` extension, **not** in Go code
- Timestamps: `TIMESTAMPTZ NOT NULL DEFAULT now()` for both `created_at` and `updated_at`
- Create a new migration: `make migrate-create`

### sqlc Queries

- Query files: `db/queries/<name>.sql`
- After any change: `make sqlc` — regenerates `db/sqlc/`
- Never edit files in `db/sqlc/` — they are fully generated
- Use `RETURNING *` on INSERT when the service needs the created row back

### Running Migrations

```sh
make migrate-up       # apply
make migrate-down     # rollback one
make migrate-status   # check state
```

## DTOs (dto.go)

- Request structs: suffix `Request` (e.g. `SignUpRequest`)
- Response structs: suffix `Response` (e.g. `BoardResponse`)
- Always use `json` struct tags with snake_case keys
- Always add `validate` tags for input structs

```go
type SignUpRequest struct {
    Email    string `json:"email"    validate:"required,email"`
    Password string `json:"password" validate:"required,min=8"`
}
```

### Response envelope pattern

All responses use a **root key** wrapper — never return a bare struct or array.

- Data struct: plain suffix `Response` (e.g. `BoardResponse`) — reusable, no wrapper
- Single resource: `Single<Name>Response` with field named after the resource
- Collection: `List<Name>Response` with plural field

```go
type BoardResponse struct {
    ID   string `json:"id"`
    Name string `json:"name"`
}

type SingleBoardResponse struct {
    Board BoardResponse `json:"board"`
}

type ListBoardsResponse struct {
    Boards []BoardResponse `json:"boards"`
}
```

This allows adding metadata (e.g. `total`, `page`) without breaking changes.

## Validation

Use `validator.Validate(&req)` from `internal/platform/validator`.

```go
if err := validator.Validate(&req); err != nil {
    return err  // *apierrors.APIError 422 with per-field details
}
```

- Validation errors return `422 Unprocessable Entity`
- Field keys in `details` match `json` tag names (not Go field names)
- Error values are i18n keys for the frontend: `"required"`, `"email"`, `"min:8"`

## Error Handling

Return `*apierrors.APIError` directly from handlers, services, and repositories.
The global `ErrorHandler` in `internal/app/errors.go` catches all errors.

```go
// Available constructors in internal/platform/apierrors:
apierrors.BadRequest("message")            // 400
apierrors.Unauthorized("message")          // 401
apierrors.Forbidden("message")             // 403
apierrors.NotFound("message")              // 404
apierrors.Conflict("message")              // 409
apierrors.UnprocessableEntity("msg", nil)  // 422
apierrors.Internal("message")              // 500
```

Error response shape:

```json
{
  "error": {
    "code": "conflict",
    "message": "user already exists"
  }
}
```

## Layer Responsibilities & Parameter Passing

Each layer accepts parameters appropriate to its abstraction level:

- **Handler** → passes `*Request` DTO to service
- **Service** → accepts `*Request` DTO; performs business logic (hashing, validation, etc.) before calling repo
- **Repository** → accepts only **primitives** (`string`, `int`, `time.Time`, etc.) — no DTO dependencies

```go
// Service calls repo with primitives
func (s *service) CreateUser(data *SignUpRequest) (SignUpResponse, error) {
    hash, err := hashPassword(data.Password)
    // ...
    user, err := s.repo.CreateUser(ctx, data.Email, hash)
}

// Repository interface uses only primitives
type Repository interface {
    CreateUser(ctx context.Context, email, passwordHash string) (sqlc.User, error)
}
```

## Handler Pattern

```go
func (h *handler) SomeAction(ctx fiber.Ctx) error {
    var req SomeRequest

    if err := ctx.Bind().Body(&req); err != nil {
        return apierrors.BadRequest("invalid request body")
    }

    if err := validator.Validate(&req); err != nil {
        return err
    }

    resp, err := h.service.SomeAction(&req)
    if err != nil {
        return err
    }

    return ctx.Status(fiber.StatusCreated).JSON(resp)
}
```

- Use `ctx.Bind().Body()` — Fiber v3 replacement for deprecated `BodyParser`
- Validate immediately after binding
- Return service errors directly — they are already typed `*apierrors.APIError`

## Key Conventions

- All constructor functions for internal types are **unexported** (`newService`, not `NewService`)
- Module-level helpers (e.g. `hashPassword`) live in `utils.go` in the module package
- `db/sqlc/` is auto-generated — run `make sqlc` after changing any file in `db/queries/`
- Body limit: 1 MB (set in server.go)
- Content-Type for all responses: `application/json`
